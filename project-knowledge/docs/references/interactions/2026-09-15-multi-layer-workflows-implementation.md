# 複数レイヤー初期化と単一レイヤー分割の実装記録

利用者の依頼を根拠に、`project-knowledge` Skillは複数レイヤーの新規`init`と、既存の単一レイヤーを新しいレイヤーへ分ける明示的な`split`を追加する。両方の操作は、先に確定したレイヤー定義と配置表を入力にし、AIが処理途中や再開時に分類、ID、パスを再推論しない。

複数レイヤーの`init`は、全レイヤーの管理骨組みと本文候補を準備・検査してから、`project-knowledge.yaml`を最後に公開する。空初期化は本文収集を省略できるが、定義、形式、登録の検査は維持する。各レイヤーのPolicyと書込み権限を維持し、読み取り専用レイヤーを初期化後に一時的に書込み可能へ切り替えない。読み取り専用の新規レイヤーも、登録前に必要な初期内容を準備してからその権限で登録する。初期化の骨組み保存直前に中断した場合は、`pending_create`記録により同じ確定定義から再開する。

`split`は通常の`update`や`refactor`と独立した操作であり、元レイヤーと明示した新規移管先だけを変更する。全対象文書を「元に残す」または一つの移管先へ置く配置表に記載する。共有Reference、User Statement、Interactionはprovenanceを維持して必要な移管先へ複製できるが、Concept本文はこの操作で分割・複製しない。本文リンクと`docs/`基準の`source`を最終配置から再計算し、state・キャッシュ・publish成果物は複製しない。

切替前に原本と指紋を操作用の一時領域へ記録し、候補を検査する。適用時はロックにより新規のKnowledge操作を停止し、入力、根拠、候補の変更を検知したら停止する。失敗時は今回の書込みだけを復旧し、他者の編集を検出した場合は上書きせず停止する。設定の公開は最後とし、既存コメントを保持する。ロックだけを削除して継続する復旧を許可しない。新レイヤーのstateは複製せず、source snapshotも無効化して再構築対象にする。元レイヤーを廃止する場合は、履歴の移管先`history_layer`を明示的に決める。通常の`verify`、`publish`、`audit`はこのフローから自動起動しない。

この記録は現行のSkill Referenceとruntime scriptsの実装差分を根拠にした契約である。全体テストの最終結果は、この記録に含めない。
