# Format 1.0

```yaml
format: project-knowledge
format_version: "1.0"
```

`format_version`は文字列としてquoteする。

## Management files

- `manifest.yml`: Knowledge Baseの形式と版
- `knowledge-policy.md`: 機械が読む運用設定と、人間・AIが読む育成・品質Policy
- `state.yml`: working copy固有の再構築可能な機械状態。欠落してもKnowledge形式1.0の正本は壊れない。

`knowledge-policy.md`は`knowledge.human_readable`のboolean値と、`manual`、`opportunistic`、`aggressive`のいずれかである`learning.mode`をfrontmatterに持つ。未知キーは許容するが、既知キーの不正型や未知のmodeを推測して修正しない。

state内部形式と復旧規則は[state.md](../state.md)で定め、Knowledge形式とは分離する。

## OKF bundle

`project-knowledge/docs/`はOKF v0.2 bundleである。通常Conceptはparse可能なYAML frontmatterを持ち、空でない`type`、`pk_category`、`pk_derivation`を含む。`sources`の各項目には`resource`と`pk_source_type`を含める。

- root `index.md`のfrontmatterは`okf_version: "0.2"`だけを持つ。
- nested `index.md`とroot・nested `log.md`はfrontmatterを持たない。
- `log.md`の見出しは日付形式にする。
- 本文リンクはMarkdownファイルからの相対パス、`sources[].resource`はbundle root基準のパスまたは有効なURIとして解決する。

OKF標準外のProject Knowledge独自fieldには`pk_`を付ける。`type`、`status`、`sources`、`generated`、`verified`、`stale`、`stale_after`はOKF fieldなので改名しない。管理ファイルとKnowledge Policyの運用設定はConcept metadataではないため、このprefix規約の対象外とする。
