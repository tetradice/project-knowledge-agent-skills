# 情報源と調査

## Authority

主張の種類ごとに authority を判断する。

- 現在の実装状態: 現在のコードと設定
- 要件と業務ルール: その内容を明示する trusted raw source
- 確定済み設計判断: その判断を明示する trusted raw source
- 現在の外部状態: アクセス可能な実環境
- 変更の経緯と基準: Gitの状態、diff、log
- 正式な情報源へ未統合で、後から復元できない情報: `project-knowledge/pending.md`

情報源が競合する場合は、各情報が表す種類と authority を確認する。
authority の対象が異なる場合は両方と不一致を保持する。
同じ authority の情報が競合して解決できない場合は、推測で選ばず報告する。
会話履歴は補助情報とし、安定した情報源から復元できる主張の正本にはしない。

## Git 状態

Git リポジトリの場合は、調査開始時にルート、完全長の `HEAD`、作業ツリーの状態を確認する。
Git 履歴を利用できない場合も処理を続け、`git_base_commit` を省略して理由を報告する。
作業ツリーが dirty の場合は、その事実を完了時に報告する。

## 調査範囲

1. `project-knowledge/index.md` が存在する場合は、索引と対象コンセプトを読む。
2. 対象コンセプトの `sources` を確認する。
3. 関連する trusted raw source、コード、設定だけを調査する。
4. `git_base_commit` が有効なら、現在の `HEAD` までの差分を調査範囲の手掛かりにする。
5. 必要かつアクセス可能な場合だけ外部環境を確認する。

未登録の資料は、ファイル名、依頼、対象コンセプトから関連性を合理的に推測できる場合だけ調査する。
`git_base_commit` からの差分だけを正本にせず、現在のコード、設定、情報源も確認する。
ナレッジや trusted raw sources を無条件に全件読み込まない。
試行錯誤、一時状態、revert済みの状態を無視し、各情報源が表す最終状態、要件、設計判断を調査する。

## 保護規則

`project-knowledge/references/` と配下の資料を、人間管理の読み取り専用入力として扱う。
通常の operation では、内容、形式、名前、配置を変更せず、削除しない。
ユーザーが資料自体の変更を明示した場合は、この Skill の operation と分けて扱う。

パスワード、API キー、トークン、秘密鍵、認証情報、`.env` の値を保存、表示、報告しない。
必要な場合は変数名、用途、取得元、非秘密メタデータだけを記録する。
外部環境や情報源を確認できない場合は推測せず、未確認であることを報告する。
