# 形式

ナレッジのルートを `project-knowledge/` とし、OKF v0.2 の Markdown と YAML frontmatter で記述する。
AI が解釈するために必要な情報だけを残し、長文より見出し、箇条書き、キーと値を優先する。
人間向けの説明文は追加しない。

## ディレクトリ構造

次のファイルを必須とする。

- `index.md`: ナレッジ索引
- `pending.md`: 後から復元できない未反映情報

システムの理解に必要な場合だけ、`system.md`、`architecture.md`、`runtime.md`、`data-model.md`、`api.md`、`integrations/` などを追加する。
独立した概念が生じた場合またはファイルが肥大化した場合だけ分割する。

`project-knowledge/references/` は任意の入力ディレクトリとする。
人間または外部から与えられ、継続して信頼する資料を形式を変えずに配置する。
これらの資料を trusted raw sources と呼ぶ。
trusted raw sources を OKF コンセプトとして `index.md` に列挙しない。

## index.md

frontmatter には次の値だけを記述する。

```yaml
---
okf_version: "0.2"
---
```

本文には各ナレッジへのリンクと短い説明を記述し、`pending.md` へのリンクも含める。

## コンセプト

コンセプトファイルには現在の安定した状態を記述する。
要件、設計判断、現在の実装、現在の外部状態が異なる場合は区別し、不一致を残す。

次の内容は記録しない。

- 推測
- 試行錯誤やrevert済みの状態
- 作業日誌や詳細な変更履歴
- ソースコードから容易に復元できる説明

本文から情報源を示す場合は、`sources[].id` と一致する脚注を使う。

```md
認証にはメールリンクを使用する。[^auth-spec]

[^auth-spec]: `sources[id=auth-spec]` を参照。
```

## pending.md

frontmatter は付けず、後から確実に復元できず、正式な情報源へ未統合の情報だけを箇条書きで記録する。
設計理由、コードへ未反映のユーザー決定、将来の制約、リポジトリから復元できない外部情報が該当する。

実装手順、一時的な試行、revert済みの変更、コードや設定から容易に復元できる情報は記録しない。
解決済みの項目を残さず、項目がなければ見出しと空である旨だけを記述する。
