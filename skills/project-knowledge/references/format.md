# 記述形式と配置

## 基本形式

ナレッジのルートには `project-knowledge/` を使用する。

次の形式で記述する。

- OKF v0.2
- Markdown + YAML frontmatter
- AI が解釈できる最小限の記述
- 長文よりも見出し、箇条書き、キーと値を優先した構成

人間向けの説明文は追加しない。

## ディレクトリ構造

次のファイルを必須とする。

- `index.md`: ナレッジ索引
- `pending.md`: 後から復元できない未反映情報

その他のファイルは必要に応じて作成する。

例:

- `system.md`: 小規模プロジェクトの統合仕様
- `architecture.md`: 構成、責務、境界
- `runtime.md`: 実行、ビルド、デプロイ、環境
- `integrations/`: 外部サービス
- `data-model.md`: データ構造
- `api.md`: API 仕様

ファイルを過剰に分割しない。ファイルが肥大化した場合や、独立した概念が生じた場合だけ分割する。

## index.md

ルートの `index.md` には、次の frontmatter を記述する。

```yaml
---
okf_version: "0.2"
---
```

本文には、各ナレッジへのリンクと短い説明だけを記述する。

```md
# コア
- [システム](system.md) - 現在のシステム仕様。

# 作業中
- [未反映事項](pending.md) - 後から復元できない未反映情報。
```

原則として `index.md` から参照を始め、必要なファイルだけを読む。

## ナレッジ本文

本文には現在の状態だけを記述する。

```md
# 認証

- Google ログイン: 対応
- 未ログイン利用: 可能
- ログイン: 任意
```

長い説明文は避ける。

## 情報分類

次の情報を記録する。

- 現在のシステム仕様
- アーキテクチャ
- 重要な制約
- 外部サービス構成
- 実行、デプロイ環境
- コードから自明でない設計判断
- AI が後続作業で必要とする情報

次の情報は原則として記録しない。

- 一時的な実装状態
- 試行錯誤
- revert 済みの変更
- 作業日誌
- 詳細な変更履歴
- ソースコードから容易に復元できる冗長な説明
- 秘密情報

## セキュリティ

次の値を保存、表示、報告しない。

- パスワード
- API キー
- アクセストークン
- 秘密鍵
- 認証情報
- `.env` の値

必要な場合は、変数名、用途、取得元、非秘密メタデータだけを記録する。
