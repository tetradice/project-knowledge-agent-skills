# check

## 検証

ファイルを変更せず、`evidence.md` の authority と調査範囲に従って次を確認する。

- `sources[].resource` を参照でき、コンセプトの内容と一致するか
- `generated`、`verified`、`git_base_commit` が現在状態と整合するか
- 現在の実装、外部状態、要件、設計判断が区別されているか
- 同じ authority の情報源が矛盾していないか

## 報告

差異、矛盾、取得できない情報源、未検証または根拠不足の内容を、該当する項目だけ分類して報告する。
差異がない範囲も一文で示す。
解決できない矛盾は推測で選ばない。

最後に、検証によるファイル変更がないことを確認する。
