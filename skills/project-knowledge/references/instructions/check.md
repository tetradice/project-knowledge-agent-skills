## 原則

検証中は `project-knowledge/` を変更しない。試行錯誤、一時変更、revert、手戻りを現在状態として扱わない。

## 調査

`evidence.md` の優先順位と調査範囲に従い、次の点を追加で確認する。

1. 関連コンセプトの `sources` と `resource` を参照できるか、その内容が現在も一致するか確認する。
2. `generated` と `verified` の時系列を確認する。
3. `git_base_commit` が有効な場合は、そこから現在の `HEAD` までの差分を調査範囲の手掛かりにする。
4. 最終的な状態とナレッジを照合する。

外部環境を確認できない場合は推測せず、未確認であることを報告する。既存値を無条件に正しいとみなさない。

秘密値を表示、報告、保存しない。

## 完了報告

次の項目を区別して報告する。

- 現在状態と一致する内容
- 現在状態との差異
- 取得できない情報源
- 未検証または根拠不足の内容
- Git 履歴を調査範囲に利用できなかった場合は、その理由

最後に、検証によるファイル変更がないことを確認する。
