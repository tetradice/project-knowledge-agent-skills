## 原則

検証中は、trusted raw sources を含むファイルを変更しない。試行錯誤、一時変更、revert、手戻りを現在状態として扱わない。

## 調査

`evidence.md` の authority と調査範囲に従い、次の点を追加で確認する。

1. 関連コンセプトの `sources` と `resource` を参照できるか、その内容が一致するか確認する。
2. `sources` に trusted raw source が含まれていれば、その資料を確認する。
3. 関連資料の存在がファイル名、ディレクトリ構造、ユーザー依頼、対象コンセプトから合理的に推測できる場合は、`sources` に未登録でも必要な範囲だけ調査する。
4. `generated` と `verified` の時系列を確認する。
5. `git_base_commit` が有効な場合は、そこから現在の `HEAD` までの差分を調査範囲の手掛かりにする。
6. 現在の実装や外部状態、要件、設計判断を区別してナレッジと照合する。

外部環境を確認できない場合は推測せず、未確認であることを報告する。既存値を無条件に正しいとみなさない。

秘密値を表示、報告、保存しない。

## 完了報告

次の項目を区別して報告する。

- 現在状態と一致する内容
- ナレッジと現在実装の差異
- ナレッジと trusted raw source の差異
- 要件と現在実装の差異
- 外部環境と記録内容の差異
- 相互に矛盾する trusted raw sources
- 取得できない情報源
- 未検証または根拠不足の内容
- Git 履歴を調査範囲に利用できなかった場合は、その理由

同じ authority の trusted raw sources が矛盾し、解決できない場合は推測で選ばず報告する。

最後に、検証によるファイル変更がないことを確認する。
