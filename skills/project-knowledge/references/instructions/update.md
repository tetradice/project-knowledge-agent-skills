# update

次のファイルを最後まで読む。

1. [../format.md](../format.md)
2. [../metadata.md](../metadata.md)
3. [../evidence.md](../evidence.md)

## 原則

ユーザーが更新を明示した場合だけ、正式なナレッジを変更する。試行錯誤、一時変更、revert、手戻りを反映しない。

## Git 状態と調査範囲

ナレッジを変更する前に、`evidence.md` に従って Git 状態を確認する。Git 管理外や初回コミット前で完全長 SHA を取得できない場合は、ファイルを変更せず中断する。

作業ツリーが dirty でも更新は続ける。`git_base_commit` には作業ツリーの基準となる `HEAD` を記録し、完了時に dirty だったことを報告する。

`evidence.md` の調査範囲に従い、関連するコンセプトだけを調査する。

## 更新

- 影響するファイルだけを更新する。
- `format.md` の形式に従う。
- 現在状態と矛盾する記述を修正または削除する。
- 不要になった記述を残さない。
- 必要な場合だけファイルを追加または分割する。
- 概念の追加、削除、改名時だけ `index.md` を変更する。
- 作業経緯ではなく最終状態を記録する。
- 通常は変更履歴を残さない。

変更する各コンセプトの frontmatter を、次の順序で更新する。

1. 実際に参照した情報源だけを `sources` に残し、各項目へ `resource` を記録する。
2. `generated.by` を実行 actor、`generated.at` を現在の UTC 日時に更新する。
3. 調査開始時に取得した完全長 SHA を `git_base_commit` に記録する。
4. コンセプト全体を `sources` または `resource` と照合する。
5. 照合に成功した場合だけ、実行 actor の `verified` 項目を現在の UTC 日時へ更新する。

同じ actor の古い `verified` 項目は置き換える。他の actor の項目は保持する。照合できなかった場合は新しい検証を記録せず、理由を完了時に報告する。

`git_base_commit` は変更するコンセプトだけ更新する。変更しないコンセプトを同じ SHA へ揃えない。`index.md` には追加しない。

## pending.md

`project-knowledge/pending.md` は、後から確実に復元できない次の情報だけを一時保存する。

- 設計理由
- 将来の制約
- コードへ未反映のユーザー決定
- リポジトリから復元できない外部情報
- 将来作業に必要な重要前提

実装手順、作業内容、一時的な試行、revert 済み変更、コードや設定から容易に復元できる情報、秘密情報は記録しない。

更新時は次の順序で処理する。

1. 関連する pending 項目を正式なナレッジへ統合する。
2. 統合済みまたは不要になった項目を `pending.md` から削除する。
3. 未解決項目だけを残す。

## 完了確認

- 更新内容が現在の状態と一致する。
- revert 済みの状態を含まない。
- 根拠のない推測がない。
- `sources` が実際に参照した情報源だけを含む。
- `generated` と `git_base_commit` が変更したコンセプトで更新されている。
- `verified` が実際の照合結果と一致する。
- 現在の検証として扱う `verified.at` が `generated.at` 以降である。
- `index.md` の frontmatter が `okf_version` だけである。
- `pending.md` の処理漏れがない。
- 不要なナレッジファイルを変更していない。
